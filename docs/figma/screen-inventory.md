### MOD-001 shared shell build notes (2026-08-22)

- Built all 4 shared frames (Header, Footer, Sidebar expanded/collapsed) as one real `AppShell` composition, per explicit task requirement that Header/Footer/Sidebar visual structure stay identical across every role while only Sidebar menu content varies. `Header.jsx`/`Footer.jsx` take no `role` prop and render unconditionally; `Sidebar.jsx` renders identical chrome (logo header, footer user card, expand/collapse toggle) for every role, filtering only the nav item list via `useVisibleNav(role)`.
- **Real product decision, escalated to and confirmed by the user before building** (agent-rules.md §3): the permission-driven RBAC design (nav items declare required permissions; a `ROLE_PERMISSIONS` map per role filters them) over a flatter static role-to-items table, and the 4-role catalog — Super Admin, Organization Admin (both named in agent.md §9.2/§10.1), Data/ETL Engineer (matches the Figma Sidebar footer's own "Jane Doe / Data Engineer" content), and Viewer (read-only, project addition — not named in agent.md or Figma). See `frontend/src/features/shell/rbac/permissions.js` for the full rationale and permission catalog.
- MOCK BOUNDARY: `frontend/src/features/shell/state/sessionSlice.js`'s `currentUser`/`role` are hardcoded (default role Data/ETL Engineer) — no MOD-002 (Auth/Session) or MOD-003 (RBAC/Permissions) backend exists yet to source a real authenticated session's role. `roleChanged`/`sidebarToggled` actions exist so the shell is real, dispatchable state, not a static mock, but the session's *origin* is still mocked. Header's org-switcher/notification-dot and Footer's live stats (active pipelines, workers, queue depth, throughput) and Sidebar's "Errors" badge count all reproduce Figma's literal shown values for the same reason (no MOD-004/MOD-008/MOD-009/MOD-010 backend yet).
- `DashboardScreen.jsx` (SCR-009) was migrated from its temporary `AppShellScaffold.jsx` scaffold to this real `AppShell` — that scaffold file was deleted. `SettingsShellScaffold.jsx` (SCR-007) was **not** migrated in this pass (it has settings-specific side-nav/breadcrumb logic beyond a simple swap); tracked as a documented follow-up in `docs/reviews/review-log.md`'s Open Issues, not done here per agent-rules.md §9 scope control.
- Every Sidebar nav item now routes to a real path; destinations with no built screen yet render a shell-wrapped `RoutePlaceholder` (added ~26 new routes in `frontend/src/app/router.jsx`) rather than dead-ending, without fabricating those screens' real content ahead of their own frontend-screen-builder pass.
- UI review (`docs/reviews/review-log.md`) found and fixed one blocker (a new sidebar section-heading color token reintroduced the exact WCAG-AA-contrast-on-real-text defect class already fixed once at SCR-001) and one high-severity gap (no `focus-visible` state on any Sidebar interactive control, breaking the Header/DashboardScreen convention) before this unit passed.
